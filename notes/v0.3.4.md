# Genealogy Skills v0.3.4

Prepared locally for review: three independent AI agent skills for family-history
research, interview processing and evidence review. This preparation does not
create a tag, GitHub release or directory listing and does not install the
rebuilt packages.

## Included skills

- **genealogy-researcher** — investigate a focused question, keep source and
  search locators, and preserve unresolved candidates and a resumption point.
- **family-interview-to-tree** — turn testimony into source-linked proposals,
  retaining speakers, corrections, unnamed people, counts and unresolved mentions.
- **genealogy-evidence-review** — compare candidates and contradictory claims,
  distinguish source dependence and preserve already accepted owner decisions.

Each skill includes its own references and license. It can be used independently;
no private archive application, companion skill or shared database is required.
The optional transfer format remains `genealogy-handoff-1`; Markdown is supported.

## Changes in 0.3.4

- Validate documented immediate person/source references inside `claim.value`
  and require the second participant of documented binary kinship predicates.
- Clarify omitted relationship participants: preserve an unresolved lead when
  the source does not identify both people. An explicit possessive still
  supports the corresponding relationship.
- Preserve original alphabets in synthetic source material while retaining
  independent privacy, path, file-set, checksum and link checks.
- Include eight paired synthetic cases, separate grading criteria, attributed
  first-response copies with declared path-only redactions and the unchanged
  known-failure response supplied with the review.
- Prepare OpenAI and Anthropic plugin profiles using the same three-skill core,
  with target-specific manifests, licenses, provenance and offline verification.
- Include standalone plugin build tools/templates, focused regressions and an
  offline repeat-build/verification check in the clean public source and CI.
- Update installation guidance and compatibility reporting after isolated native
  client checks. The earlier artifacts and first responses remain preserved.

The format version has not changed. Typed references and missing binary
participants that an older validator tolerated now fail. Correct source-backed
links or retain an unresolved lead; do not invent a person to make a handoff pass.

## Prepared archive types

- **Consumer ZIP:** standalone skill folders, English documentation, synthetic
  examples/evaluation evidence and optional Python checks.
- **Clean source ZIP:** the selected public-source file set and CI/support files,
  without the mixed integration repository's Git history or unrelated skills.
  It includes core/evaluation tooling, both plugin profiles' build support,
  pinned templates/schema/license and focused regressions. Earlier frozen source
  archives retain their original inventories; they are not relabeled or changed.
- **OpenAI plugin ZIP:** root `plugin.json`, presentation metadata and the three
  skills, plus the applicable offline verification and license files.
- **Anthropic plugin ZIP:** `.claude-plugin/plugin.json` and the same three skills,
  plus the applicable offline verification and license files.

Use the README in the chosen archive; standalone and plugin commands differ.
Exact asset names, source commit, sizes and SHA-256 values are supplied in the
artifact-specific delivery receipt. Package manifests identify their own
contents. The skill runtime is pinned to public core commit
`f095c56cb78b09a28beb98ee0ac14e054eb7325c`; documentation/wrapper work has
its own committed source revision. Do not relabel an older candidate as this
prepared asset or treat a proposal branch as an already published main revision.

## Verification and limits

On 2026-11-06, isolated Codex CLI 0.166.0 tests temporarily installed the plugin,
discovered exactly three plugin skills and completed three explicit synthetic
supplied-text tasks. All original JSONs pass the handoff validator; independent
content/scope assessment passes all 21 criteria. The configured model was
`gpt-6.1-sol` with low reasoning effort; the trace did not independently return a
server-side model identity. The interview invocation warned of inline truncation,
then read its complete installed instruction and references before answering.
The other two calls had no such warning. No first response was repaired or rerun.

Claude Code 2.1.206 native init registered all three plugin skills and slash
commands. Its attempted model call stopped at authentication; the test account
did not have an eligible subscription. No real Claude model response is claimed.
Temporary native test installations/profiles were removed after that check.

The final archive preparation updates documentation and performs offline package
checks without another installation or model run. The runtime remains unchanged
from the tested core. Automatic skill selection, ChatGPT GUI/Cowork, other hosts,
live archive access, general genealogical accuracy and improvement over the same
model without skills remain unverified. These three native cases do not provide
a reliability percentage.

Findings are proposals, not accepted tree changes. The skills do not include a
tree importer, case database, automatic workflow engine or DNA processing.
Checksums detect changed bytes; they are not a signed authenticity guarantee.
The instructions do not create a technical sandbox or grant external access.
